`user?.profile?.name` 은 편합니다. 그런데 편해서 생기는 문제가 있습니다.

## 에러가 사라진 것이 아니다

API 응답 형태가 바뀌어 `profile`이 오지 않게 된 상황에서,
옵셔널 체이닝은 예외 대신 `undefined`를 돌려줍니다.
화면에는 빈 칸이 뜨고, 로그에는 아무것도 남지 않습니다.
잘못된 데이터가 조용히 통과합니다.

## 어디에 쓰고 어디에 쓰지 않을까

- **쓴다**: 정말로 없을 수 있는 값 (선택 입력 필드, 조건부 콜백)
- **쓰지 않는다**: 반드시 있어야 하는 값. 없으면 그 자리에서 실패하는 편이 낫습니다

```js
if (!user.profile) {
  throw new Error("profile is required in user response");
}
```

## 정리

방어 코드는 예상한 결측값에만 붙입니다.
예상하지 못한 결측값은 빨리, 시끄럽게 실패하는 쪽이 고치기 쉽습니다.
